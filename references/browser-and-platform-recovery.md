## BOSS Browser Self-Recovery

目标是由 Agent 自行恢复普通浏览器故障，只把必须由用户本人完成的身份验证、安全验证、连接修复或平台风险处理交给用户。

- 当 `browser connected == true` 时，空白页、`about:blank`、页面丢失、DOM 暂时不可读或普通加载失败都先自动诊断，不得立即要求用户手动打开 BOSS。
- 默认复用已有 BOSS 标签页或当前可控标签页，不要反复创建新标签页。
- 设定 `MAX_RECOVERY_ATTEMPTS = 3`。每次恢复后重新读取 URL、标题、DOM 或可见内容；只有检查过状态变化后才进入下一次尝试。
- 一旦识别为登录、验证码、安全验证或平台限制，立即停止普通恢复；不得用刷新、换标签页或重复导航绕过。
- 恢复网页不扩大操作权限。未获确认时仍不得发送消息、投递、上传简历或提交表单。

## Recovery Context

浏览器操作前和每个已完成步骤后维护：

```text
Task: 当前求职任务
Location: 城市或通勤范围
Keywords: 搜索关键词
Exclude locations: 排除地区
Exclude companies: 排除公司
Candidate pool: 当前候选岗位及唯一标识
Analyzed: 已分析岗位和公司
Applied: 已有明确页面证据的已投岗位
Current page: URL、标题、页面类型
Last completed: 最近完成的动作
Next action: 恢复后应执行的下一步
```

页面异常不能清空这些信息。恢复后从 `Next action` 继续，不要从头重跑任务。

## Browser Failure Classification

| 分类 | 判断信号 | 动作 |
| --- | --- | --- |
| `TRANSIENT_PAGE_ERROR` | 页面暂时空白、未加载完成、DOM 暂时不可读、普通网络加载异常 | 在有限次数内自动重试并检查状态变化 |
| `TAB_NAVIGATION_ERROR` | `about:blank`、新标签页、URL 丢失、当前标签页不是 BOSS、导航后页面消失 | 优先切换已有 BOSS 标签页；否则在当前标签页导航到 BOSS |
| `CONNECTOR_DISCONNECTED` | 无法读取窗口或标签页，浏览器工具明确报告连接断开 | 请求用户重新连接 Chrome 插件 |
| `LOGIN_REQUIRED` | BOSS 登录页或明确的未登录状态 | 暂停并请用户本人登录；不输入密码，不读取短信验证码 |
| `CAPTCHA_REQUIRED` | 验证码、滑块、人机验证、短信验证或安全验证 | `PLATFORM_RISK_PAUSE`，请用户本人完成，不得绕过 |
| `PLATFORM_LIMIT` | “操作频繁”“访问受限”“账号异常”或其他明确风控提示 | `PLATFORM_RISK_PAUSE`，停止操作，不刷新或换标签页绕过 |
| `WEBSITE_UNAVAILABLE` | Chrome 连接正常，但 3 次有状态检查的恢复仍无法打开 BOSS | 报告每次检测结果，请用户检查网络或浏览器 |

优先依据浏览器工具的明确状态、当前 URL 和页面可见文字分类。证据不足时，不把普通空白页误判为连接断开、登录失败或平台风控。

## 恢复顺序

### Step 1：检查 Chrome 连接

1. 读取当前窗口和标签页列表。
2. 确认浏览器工具是否仍能读取标签页、URL 或标题。
3. 只有工具明确断开或完全无法读取浏览器状态时，分类为 `CONNECTOR_DISCONNECTED` 并请求用户重新连接。
4. 连接仍正常时继续自动恢复，不要让用户回复“已打开”。

### Step 2：查找已有 BOSS 标签页

1. 检查当前窗口全部标签页，寻找 URL 包含 `zhipin.com` 的页面。
2. 如果存在，优先切换到已有 BOSS 标签页，不要新建标签页。
3. 读取 URL、标题和可见内容，判断它是职位页、搜索页、首页、登录页还是验证或限制页。
4. 已有正常 BOSS 页面时，直接从 `Next action` 继续任务。

### Step 3：复用当前标签页恢复空白页

当前标签页为 `about:blank`、新标签页、URL 丢失或非 BOSS 页面，且没有其他正常 BOSS 标签页时：

1. 在同一可控标签页直接导航到 `https://www.zhipin.com/`。
2. 导航后重新读取 URL、标题、DOM 或可见内容和主要页面元素。
3. 根据新证据重新分类；正常加载就结束恢复并继续任务。

不要把“创建新标签页 → 打开 BOSS”作为默认方式。只有当前标签页不可导航且工具允许受控创建时，才创建一个新标签页，并且只创建一个。

### Step 4：有限自动重试

一次导航、reload 或重新导航计为一次恢复尝试，最多 3 次：

1. 第一次：优先切换已有 BOSS 标签页；没有则在当前标签页导航到 `https://www.zhipin.com/`。
2. 检查 URL、标题、可见内容和页面类型，记录与恢复前相比的变化。
3. 若属于 `TRANSIENT_PAGE_ERROR`，第二次使用 reload，并再次读取状态。
4. 若仍是普通页面错误，第三次在同一标签页重新导航到 BOSS 首页，并再次读取状态。
5. 任一步发现登录、验证码、安全验证或平台限制，立即停止后续重试并按对应分类处理。
6. 3 次后仍无正常页面，分类为 `WEBSITE_UNAVAILABLE`；不得继续机械刷新。

如果某次动作没有产生任何状态变化，不要重复同一动作；进入下一种有限恢复动作并保留检测记录。

## 恢复成功后的任务续接

恢复成功后自动执行 `Recovery Context.Next action`。只读搜索、筛选、评估和公司去重不需要再次确认。

例如原任务为“筛选肇庆外贸/跨境岗位，排除四会、金德斯”，恢复后继续：

1. 搜索肇庆外贸或跨境岗位；
2. 排除四会地区和金德斯；
3. 按公司和岗位链接去重；
4. 执行 Hard Gate 和风险分析；
5. 更新候选池并输出候选岗位。

不要询问“网页恢复了，是否继续”。

## 防止重复工作

恢复后先用公司名、岗位名、岗位链接或页面可见的稳定标识核对状态：

- 已读取的岗位不重复读取；
- 已分析的公司不重复分析；
- 已加入候选池或已排除的岗位不重复加入；
- 只有 BOSS 页面明确显示投递成功时才记录为已投；
- 已投岗位不得因页面恢复而再次投递。

## 用户介入范围

仅以下情况优先请求用户操作：

1. `LOGIN_REQUIRED`；
2. 短信验证码；
3. 滑块验证码；
4. 人机验证；
5. 安全验证；
6. `CONNECTOR_DISCONNECTED`；
7. 浏览器权限明确失效；
8. `PLATFORM_LIMIT`；
9. `WEBSITE_UNAVAILABLE` 或浏览器、网络完全不可用。

普通 `about:blank` 不属于必须人工介入的问题。

## 失败报告格式

只有自动诊断和有限恢复失败后，才向用户报告：

```text
Chrome 连接正常，但连续恢复后 BOSS 页面仍无法加载。
我没有进行任何投递、发送或提交操作。

当前检测到：
- 当前 URL：…
- 页面标题或可见状态：…
- 已尝试：切换已有标签页 / 当前标签页导航 / reload / 重新导航（按实际情况列出）
- 最终分类：WEBSITE_UNAVAILABLE / CONNECTOR_DISCONNECTED / LOGIN_REQUIRED / CAPTCHA_REQUIRED / PLATFORM_LIMIT

需要你处理：具体且最小的用户动作。
```

不要只说“网页有问题”，也不要在没有执行恢复步骤时要求用户“打开 BOSS 后回复已打开”。

## 页面证据与安全

- 点击不等于成功。必须读取 BOSS 页面明确结果后，才能声称已保存简历、已发送消息、已投递或对方已读。
- 不伪造 URL、页面标题、登录状态、验证码状态、风控提示或投递结果。
- 不绕过验证码、BOSS 风控或安全验证，不破解身份验证。
- 页面恢复后仍严格执行主 Skill 的投递确认门槛。
