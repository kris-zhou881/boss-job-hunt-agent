# 投递跟踪与投递前检查

仅在准备投递、读取消息、更新申请状态或复盘时读取。

## Pre-Apply Check

提交前逐项确认：

1. Hard Gate 为 `PASS`，没有用户明确排除项；
2. 公司风险不是 `CRITICAL`，高风险已由用户决定；
3. 本岗位已去重，未重复沟通或投递；
4. JD、薪资、地点、招聘人活跃状态和岗位链接仍可见；
5. 使用已有 BOSS 简历时核对版本与事实来源；如需改写在线简历，用户已确认拟写入的完整内容；
6. 打招呼文案针对当前岗位，且不包含未经确认的事实；
7. 用户已设定当天外部动作上限，且未触及上限或平台风险暂停；
8. 当前公司和岗位在用户明确授权的单岗或有界批次条件内；用户若已免除逐家确认，无须点击前再次询问；
9. 本次文案已逐条核对，所有经历、数字、客户、证书和结果均有 `Confirmed` 事实来源。

任何一项不通过，转到对应待确认、风险复核或暂停状态，不提交。

### GUI 附件简历检查

使用桌面 GUI 或 BossClaw 补发附件时，再确认：

1. 当前会话的公司、招聘人和岗位与目标完全对应；
2. 对方已回复或明确索要简历，岗位仍通过 Hard Gate；
3. 使用的是用户确认过的真实简历版本；
4. 普通聊天“发送”和“发送简历/发送附件”入口已区分；
5. 已记录 `Pending action`，并能读取明确的附件发送回执或本人附件气泡；
6. 没有验证码、限频或页面跳转；若工具拒绝了当前页面动作，该岗位保持待核验，不能进入发送队列，但继续处理不依赖该页面的本地工作。

没有完整证据时只能记录 `ATTACHMENT_UNCONFIRMED`，不得自动重发；首次确认成功后暂停一次，让用户核对目标、文字气泡和附件。

同账号存在并行求职任务时，只由一项任务执行外部写入；另一项不得争用浏览器标签或按相同公司名单重发。读取对方任务结论只能帮助定位待核验对象，不能代替当前 BOSS 页的历史沟通状态和送达回执。

草稿已填入但标签、焦点或浏览器控制权发生变化时，先停止发送；重新读取当前会话的公司、招聘人、岗位、草稿全文和发送按钮，五者同时对应原目标后才继续。任何一项无法核对就保留草稿并标记待核实，不猜测点击位置，也不切换控制方式绕过工具拒绝；该岗位的页面操作暂停时，可继续其他不依赖它的已授权本地准备。

## 状态机（16 状态）

| 状态 | 含义 | 允许下一步 |
| --- | --- | --- |
| `DISCOVERED` | 已发现，未去重 | 去重或淘汰 |
| `DEDUPED` | 已去重 | Hard Gate |
| `HARD_FAIL` | 明确不符合 | 结束，保留原因 |
| `RISK_REVIEW` | 需风险或信息核验 | 评估、提问或停止 |
| `RESUME_DRAFT` | 已出定制简历草稿 | 用户核对 |
| `WAITING_RESUME_CONFIRMATION` | 等待在线简历写入确认 | 写入或保留草稿 |
| `PRE_APPLY_READY` | Pre-Apply Check 通过 | 未授权时请求确认；已授权时逐条执行 |
| `WAITING_APPLY_CONFIRMATION` | 等待投递授权 | 获得授权后提交或暂停 |
| `APPLIED` | BOSS 明确显示申请已提交 | 等待后续进展 |
| `READ` | 对方已读 | 等待回复或跟进 |
| `REPLIED` | 收到回复 | 处理消息或约面 |
| `INTERVIEW_INVITED` | 收到面试邀请 | 用户确认时间 |
| `INTERVIEW_SCHEDULED` | 面试已确定 | 准备与跟进 |
| `REJECTED` | 明确拒绝或岗位关闭 | 复盘 |
| `OFFER` | 收到 Offer | 用户决策 |
| `PLATFORM_RISK_PAUSE` | 验证码、安全验证或明确的平台限流/账号限制 | 用户处理后恢复 |

不得凭点击推断 `APPLIED`；必须读取 BOSS 明确的申请状态或成功提示。沟通、附件简历和申请分别记录：`招呼状态（未联系/送达/已读/已回复/撤回/待核实）｜附件简历状态（未发送/已发送/待核实）｜申请状态（未提交/已提交/待核实）`。招呼显示“送达”不能自动写成附件已发送或申请已提交。其余字段保持：`公司｜岗位｜链接｜匹配分/置信度｜简历版本｜日期｜招聘人｜最后互动｜下一动作｜风险/备注`。

附件字段单独记录：`DRAFT_READY`（草稿/预填）、`RESUME_REQUEST_SENT`（简历请求已发，等待对方确认）、`ATTACHMENT_SENT`（附件明确已发）或 `ATTACHMENT_UNCONFIRMED`（结果不明）。这些是附件子状态，不改变上面的 16 状态机。若招呼已发但附件未确认，记录 `PARTIAL_SENT`，不计为完整投递。点击“发简历”后若只出现等待对方同意的请求，不能计为附件发送成功；点击索要卡片的“同意”也必须读取附件回执。结果不明时不得再发请求作为兜底。

消息曾显示“送达”后又出现“你撤回了一条消息”时，记录为“曾发送后撤回”，保留原发送与撤回证据；不计最终成功，也不归入“从未联系”。再次联系前必须核对当前会话并取得新的外部动作授权，不能因撤回而自动重发。用户说“停止”后，该批次剩余岗位保持未发送，原授权失效。
