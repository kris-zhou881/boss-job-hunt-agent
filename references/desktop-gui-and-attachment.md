# 桌面 GUI、附件简历与 BossClaw 适配

仅在用户明确要求使用桌面 GUI、发送附件简历，或已连接本地 BossClaw 时读取。

本文件吸收两个公开项目的可复用流程：

- [BruceWen1/boss-zhipin-apply-skill](https://github.com/BruceWen1/boss-zhipin-apply-skill)：桌面 GUI、列表内筛选、消息页跟进、把普通消息发送和“发送简历”入口分开。
- [YanQuan-dozzy/Boss-Claw](https://github.com/YanQuan-dozzy/Boss-Claw)：本地优先、草稿与发送分离、首次成功后暂停验收、目标和风控闸门、可选本地控制桥。

## 适配层选择

| 适配层 | 默认权限 | 说明 |
| --- | --- | --- |
| `CHROME_EXISTING_PAGE` | `READ_ONLY` | 现有默认路径，只绑定用户已手动打开的 BOSS Chrome 标签页 |
| `DESKTOP_GUI_REVIEW` | `READ_ONLY`/`DRAFT` | 用户指定的桌面 GUI；只读筛选、生成草稿、预填但不发送 |
| `DESKTOP_GUI_CONFIRMED` | `CONFIRMED_ACTION` | 用户已授权的有界批次；逐岗操作，发送后读取平台回执 |
| `BOSSCLAW_REVIEW` | `READ_ONLY`/`DRAFT` | 仅使用本地 BossClaw 的浏览、分析和 `deliveryDraft`；不打开全自动发送 |
| `BOSSCLAW_AUTO` | 不由 Agent 自行开启 | 只有用户已在 BossClaw 应用内明确开启全自动，且本轮授权覆盖时才可调用发送动作；仍受应用自身安全引擎约束 |

适配层切换不扩大用户授权。若当前 Chrome 页面正常，优先继续使用它；不能为了使用某个适配层而新建 BOSS 标签、导出 Cookie、启动隐藏浏览器或绕过浏览器工具拒绝。

## GUI 投递流程

1. 读取用户偏好、真实简历和本轮授权边界。
2. 在同一列表页完成城市、岗位、行业、公司黑名单和 JD 初筛；不要为每个岗位累积新标签页。
3. 逐个打开右侧详情，重新核对公司、招聘人、岗位、地点、JD 和历史沟通状态。
4. 先生成岗位对应的招呼草稿；用户授权发送后才点击“立即沟通”。
5. 读取明确平台反馈：已向 BOSS 发送消息、继续沟通、进入目标会话或已出现本人文字气泡。
6. 只有对方已回复或明确索要简历，且岗位仍通过 Hard Gate，才进入消息页补发附件简历；不能把首次“立即沟通”当作附件投递。
7. 在消息页把普通聊天“发送”和“发送简历/发送附件”两个入口分开核对；先确认会话对象，再选择正确简历版本和附件。
8. 发送附件后回读“简历已发送/附件已发送”等明确状态，或回读本人附件气泡；否则记录 `ATTACHMENT_UNCONFIRMED`，不重发。
   若页面明确显示的是“简历请求已发送，等待对方同意”，记录 `RESUME_REQUEST_SENT`，不计附件送达；点击“同意”后结果不明也不改走请求入口补发。
9. 第一次确认成功后暂停，让用户核对公司、招聘人、文字气泡和附件；验收通过后才继续剩余批次。

## BossClaw 适配规则

- `deliveryDraft` 只负责打开目标沟通并预填草稿，结果是“待用户核对”，不是已发送。
- 发送类动作只能由应用自身白名单和安全引擎执行；Agent 不得改写 `executionMode`、每日上限、冷却时间、平台列表或 API Key。
- BOSS 的主投递语义是聊天文字气泡，附件/在线简历是独立能力；两个结果必须分别记录。
- 目标会话、招聘人或岗位无法确认时拒绝发送；外部网申按钮命中时跳过，不把跳转当作 BOSS 投递成功。
- 验证码、安全验证、账号异常、频率限制、页面结构不确定或发送结果不明时暂停受影响的发送步骤；不重试、不换控制方式、不切换账号。若属于工具策略拒绝，继续其余不依赖被拒页面动作的已授权工作，并保留检查点。
- 本地控制桥或 MCP 默认只允许读状态、分析、生成草稿和暂停/恢复；只有用户在应用内开启全自动且授权覆盖时才可能放行发送。

## 附件发送前检查

- 当前会话的公司、招聘人、岗位与目标完全对应；
- 对方已回复或明确索要简历；
- 简历版本来自用户已确认的真实文件；
- 不会把普通文本发送按钮误当成附件按钮；
- 当前没有验证码、风控提示或页面跳转；
- 已记录 `Pending action` 和待核验结果；
- 本轮数量、公司去重和用户授权仍有效。

## 结果状态

| 状态 | 含义 |
| --- | --- |
| `DRAFT_READY` | 草稿已生成或预填，未发送 |
| `GREETING_SENT` | 招呼文字有明确平台回执 |
| `ATTACHMENT_SENT` | 附件发送有明确平台回执 |
| `RESUME_REQUEST_SENT` | 简历请求已发，等待对方确认，尚无附件送达证据 |
| `PARTIAL_SENT` | 招呼已确认，但附件未确认；或附件已确认但普通消息未确认 |
| `ATTACHMENT_UNCONFIRMED` | 已点击附件动作但没有明确回执，不得重发 |
| `PLATFORM_RISK_PAUSE` | 验证码、限频或账号异常，停止受影响的写操作；工具拒绝另记录为 `BROWSER_POLICY_DENIED`，只暂停依赖被拒动作的步骤 |

不要把“打开会话”“点击按钮”“招呼送达”直接写成附件已发送或申请已提交。
